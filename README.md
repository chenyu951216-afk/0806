# Gate 10X 自適應驗證雷達 v4.3

目標仍是盡量提早辨識低基期、小市值、現貨吸籌、波動壓縮後可能進入主升段的候選。任何 10X 分數或 3x／5x／10x 都不是報酬保證。

## 為什麼需要 v4.3

v4.2 的核心缺陷是「正式驗證」本身太像真人下單門檻：必須先有高分、微結構、CVD、訂單簿、BTC環境與重播全部接近完美，才開始建立 paper order。結果是系統可能掃一整晚卻連一筆可驗證樣本都沒有。

v4.3 把兩件事分開：

1. **核心策略是否有效**：用較合理但仍有結構安全限制的 FORMAL 核心驗證池真實收集樣本。
2. **現在是否值得真人下單**：仍使用原本更嚴格的即時微結構、分數、BTC與風控條件。

所以「放寬的是收集證據的門檻」，不是直接把垃圾訊號推薦成真人單。

## FORMAL 正式驗證池

EARLY 核心樣本預設要求：

- 10X 分至少 70；
- 執行分至少 62；
- 結構型 SL 合法且未失效；
- 仍處於突破前 EARLY 時點；
- 壓縮、累積量與連續量能至少達核心門檻；
- 不要求當下微結構／歷史重播已經全部達真人執行級別，這些會被寫進 snapshot 當作特徵。

RETEST 核心樣本預設要求：

- 15m 突破真的已收線；
- 執行分至少 68；
- 10X 分至少 68；
- 固定回踩區、深結構 SL 與追價結構有效；
- 過熱或結構失效仍會直接拒絕。

## 真實模擬生命週期

每筆新模擬單都從 `WAITING_FILL` 開始。

- 掃描當下即使價格剛好在區間，也不回頭假設已成交。
- 建單之後的已收 1m K 真正碰到固定限價，才轉成 `OPEN`。
- 之後逐根追蹤固定 SL、TP1、TP2、TP3、保護 SL 與 Runner。
- 同根 K 同時碰到進場與 SL 時採保守順序。
- Zeabur 停機後若無法完整補回歷史，該樣本標成 `INVALIDATED`，不亂算勝負。

v4.3 另外修正 v4.2 的一個重要 bug：**現價高於 EARLY chase cap 時，低掛在固定早期區的買單本來仍可等待回落成交，v4.2 卻直接拒絕建立模擬掛單。**現在 chase cap 只禁止你在高位追價，不會阻止後台低掛固定價格做 forward validation。

## 漸進式解鎖

### LOCKED

樣本還不足或初步績效不合格，不推薦真人系統單。

### PROBATION 試行

同一模式至少 5 筆真正成交並封閉的 FORMAL 核心樣本，且：

- PF >= 1.05；
- 期望值 >= 0R；
- 最大回撤 <= 5R。

此時仍必須當下真人執行條件全部通過，才會出現在「✅我可以下的單」。而且單筆風險會被後端強制限制為最多 `0.50%`；EARLY 首倉再乘 35%，所以實際初始風險通常更低。

### FULL 完整驗證

維持原正式標準：

- 總 FORMAL 封閉交易至少 20 筆；
- EARLY／RETEST 每模式至少 8 筆；
- PF >= 1.20；
- 平均期望值 >= 0.10R；
- 最大回撤 <= 8R。

FULL 後才允許依網站設定使用正常單筆風險（最高仍受 5% 上限與帳戶總風險限制）。

## EXPLORE 探索池

探索池比 FORMAL 更寬，只研究漏網訊號。它一樣使用 forward limit、SL、TP、Runner 追蹤，但：

- 不直接解鎖真人單；
- 不污染 FORMAL 的 PF／期望值；
- 會記錄當時缺少哪些正式條件；
- 用來之後比較低分候選是否真的值得調整正式門檻。

## Plan ID 穩定性修正

v4.2 用滑動的 base start timestamp 判斷是否同一個 Plan。這個 timestamp 每根 15m 都會變，可能造成同一個價格結構被誤判成新 Plan。

v4.3 改成比較：

- breakout trigger 的 ATR 距離；
- EARLY／RETEST 固定區重疊程度；
- 原 Plan 是否仍未到期與未失效。

同一個價格結構因此會沿用同一 Plan ID，不會每15分鐘亂換。

## 每輪掃描永久稽核

新增 `/api/scan-audit`。每輪掃描都會寫入 `/data/scanner_v2.db`：

- Universe 數；
- Deep scan 數；
- setup 數；
- FORMAL／EXPLORE 新增數；
- 最常被哪個條件擋掉。

因此「真的沒訊號」與「程式根本沒跑」可以直接區分。

## 真人下單仍然嚴格

真人推薦仍要求 `early_raw_ready` 或 `formal_raw_ready`，包含高分、即時現貨流／CVD、訂單簿品質、BTC環境、固定Plan與帳戶風控。探索或核心驗證被放寬，不等於真人執行門檻被放寬。
