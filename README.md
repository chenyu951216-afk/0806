# Gate 10X 真實驗證雷達 v4.1

目標是盡量提早辨識低基期、小市值、現貨吸籌、波動壓縮後可能進入主升段的候選。任何「10X」分數或里程碑都不是報酬保證。

## v4.1 最重要的修正

舊版模擬交易會在訊號出現時直接假設成交，無法真實回答固定限價到底有沒有碰到。v4.1 改成完整訂單生命週期：

1. `WAITING_FILL`：策略條件達標後建立固定模擬限價，但尚未成交。
2. `OPEN`：已收完的 1m K 真正碰到掛單價後才成交，從這一刻開始計算績效。
3. `CLOSED`：碰到固定 SL、保護 SL 或持有期限結束後才算一筆封閉交易。
4. `EXPIRED/CANCELLED/INVALIDATED`：未成交、到期或失效，不計入 20 筆績效。

早期佈局 `EARLY` 與突破回踩 `RETEST` 使用同一 Plan 也會分成兩筆獨立模擬策略，不互相混用。

## 哪些訊號會進入後台驗證

- **普通潛力觀察**：不建立模擬掛單。
- **只有突破、但品質不足**：不建立模擬掛單。
- **15m 突破已收線，且分數、現貨 CVD、訂單簿、BTC 環境及歷史重播全部通過**：立即建立 `RETEST` 固定回踩模擬限價，不必事後假設回踩成交。
- **10X 早期吸籌品質全部通過**：建立 `EARLY` 固定早期模擬限價。

每輪最多新增 `MAX_NEW_PAPER_ORDERS_PER_SCAN` 筆，所有活躍模擬掛單與持倉最多 `PAPER_MAX_ACTIVE_ORDERS` 筆。

## 模擬成交與績效規則

- 只處理已收完的 1m K。
- 買入限價只有在 K 線低點真正碰到掛單價時才成交。
- 若開盤已跳到掛單價下方，採較有利的實際開盤價成交；若同一根 K 同時碰到進場與 SL，採保守順序，先計入 SL。
- 若跳空穿過 SL，採保守價格計算，不假設能在更好的固定 SL 成交。
- TP1、TP2、TP3 分批計算；Runner 不會在 TP3 被虛假估值為已獲利。
- TP3 後剩餘 Runner 使用 1h 寬尾隨。
- 模擬持有超過 `PAPER_MAX_HOLD_DAYS` 會按當時價格結束，避免永遠不封閉。
- Zeabur 重啟或停機後，會分頁補抓遺漏的已收 1m K；最多回補頁數由 `MAX_TRACKING_CANDLE_PAGES` 控制。

## 驗證解鎖條件

真人系統單使用模式別驗證：

- 總封閉模擬交易至少 `MIN_PAPER_TRADES=20`。
- EARLY 或 RETEST 各自至少 `MIN_PAPER_TRADES_PER_MODE=8` 筆，該模式才可能解鎖。
- Profit Factor 至少 `1.20`。
- 平均期望值至少 `0.10R`。
- 最大回撤不得高於 `8R`。

只有真正成交並最終封閉的交易會計入；等待成交、取消與到期不算。

## 「✅我可以下的單」

首頁第一個頁籤只列出：

- 對應模式已通過模擬驗證；
- 固定 Plan 仍有效；
- 帳戶單筆風險、總風險、1 倍總名目及相關性都通過；
- 可在固定區掛限價的交易。

每張下單卡會清楚列出：

- 幣種與 EARLY／RETEST 模式；
- `LIMIT` 掛單，不把小市值幣預設成市價單；
- 即時價、固定掛單區、精確掛單價與有效期限；
- 應下名目金額及數量；
- 固定深結構 SL 與預計最大虧損；
- TP1／TP2／TP3 的價格、平倉百分比、名目金額和數量；
- Runner 保留比例、名目和數量；
- 禁止追價上限。

Gate 真正成交後，按「Gate 已成交，回填網站」，輸入真實成交價。後端會再次檢查成交價與所有風控；網站不會登入 Gate 或代替使用者下單。

## 風控

- 網站可設定單筆帳戶風險 `0.1%～5%`。
- 深結構 SL 依基底、最近結構低點、ATR 與緩衝計算，不為了湊風險而硬塞得很近。
- 名目金額由帳戶風險及 SL 距離反推。
- EARLY 預設只使用完整風險名目的 35%。
- 所有未保本持倉總風險預設最多 8%。
- 所有真人持倉總名目預設最多帳戶餘額 100%。
- 高相關與同幣種重複持倉由後端拒絕。
